# Linux (Omarchy)

This side tracks the configuration of the Arch machine running **Omarchy**
(Arch + Hyprland + the Quickshell `omarchy-shell`). Shared config (`../shared/`)
applies to both OSes.

The headless server node lives outside this folder, in `../server/`.

Verified against Omarchy `4.0.0.alpha`.

## What is versioned, and what deliberately is not

| Path | In the repo? | Why |
|---|---|---|
| `omarchy-shell/` | **yes** | the hand-made decisions: bar, tray, font size, language, branding, one hook |
| `zsh/`, `starship.toml` | **yes** | the shell: `~/.zshrc` and the Linux `pastel-powerline` prompt |
| `~/.config/hypr/` | **only `bindings.lua`, `monitors.lua` and `looknfeel.lua`** | the rest is byte-identical to `/usr/share/omarchy/config/hypr/`, so the package owns it; those three carry the chord overrides, the explicit left/right layout and the rounded corners |
| `~/.config/xdg-terminal-exec/` | **yes** | which terminal the plain-terminal chord opens (`ghostty`) |
| `~/.config/herdr/config.toml` | **yes** | `[terminal] default_shell = "/usr/bin/zsh"` — **CLI/TUI only**: that key is absent from `herdr-core` and `herdr-app`, which spawn panes from their core's `$SHELL` |
| `~/.config/omarchy/themes/` | **no** | generated by Aether (`.aether-managed` marker); regenerate, do not version |
| `~/.config/omarchy/plugins/superwhisper-panel` | **no** | a symlink into `/opt/superwhisper/`, shipped by the Superwhisper package |
| wallpaper media | `../shared/wallpapers/` | not OS-specific — see that README |

Omarchy's Hyprland config is **not** a single `hyprland.conf`: `hyprland.lua` is the
entry point and `require`s `monitors`, `input`, `bindings`, `looknfeel` and
`autostart` from `~/.config/hypr/`. Editing them is supported, and three of them
now carry a personal decision, so they are forked and listed in `MANIFEST.md`:
`bindings`, `monitors` and `looknfeel`. The rest stay byte-identical to the
package. If you edit another one, copy **that file only** and add a manifest row —
never the whole tree, because `omarchy update` is supposed to keep replacing the
rest.

**After editing a Hyprland Lua module you must reload by hand:**

```bash
hyprctl reload && hyprctl configerrors   # empty output = the file parsed
```

Hyprland auto-reloads a `.conf` it can see, but these modules are pulled in by
Lua `require`, which it does not watch. Without the reload the old bindings stay
active and the edit looks like it "did nothing" — verified on this machine.

## Install

The same contract as Windows: **copy files to their destinations, no symlinks**.
`MANIFEST.md`'s Linux table is the source of truth for every path.

```bash
git clone <this-repo> ~/verdu.dotfiles
cd ~/verdu.dotfiles

# shared
cp -r shared/nvim/. ~/.config/nvim/
mkdir -p ~/Wallpapers
cp shared/wallpapers/*.mp4 ~/Wallpapers/

# shell
sudo pacman -S --needed zsh zsh-autosuggestions zsh-completions zsh-syntax-highlighting
cp linux/zsh/zshrc ~/.zshrc
cp linux/starship.toml ~/.config/starship.toml
chsh -s /usr/bin/zsh   # takes effect on the next login

# omarchy-shell (README.md in that folder is documentation — never copy it)
mkdir -p ~/.config/omarchy/{branding,defaults,hooks/theme-set.d}
cp linux/omarchy-shell/shell.json \
   linux/omarchy-shell/shell.toml \
   linux/omarchy-shell/language ~/.config/omarchy/
cp linux/omarchy-shell/branding/* ~/.config/omarchy/branding/
cp linux/omarchy-shell/defaults/agent \
   linux/omarchy-shell/defaults/dictation ~/.config/omarchy/defaults/
cp linux/omarchy-shell/hooks/theme-set.d/10-owe-sync \
   ~/.config/omarchy/hooks/theme-set.d/
chmod +x ~/.config/omarchy/hooks/theme-set.d/10-owe-sync

# personal Hyprland modules, plain-terminal target, Herdr shell
# (the rest of ~/.config/hypr/ is package-owned — never copy the whole tree)
mkdir -p ~/.config/hypr ~/.config/xdg-terminal-exec ~/.config/herdr
cp linux/hyprland/bindings.lua linux/hyprland/monitors.lua \
   linux/hyprland/looknfeel.lua ~/.config/hypr/
cp linux/xdg-terminal-exec/hyprland-xdg-terminals.list ~/.config/xdg-terminal-exec/
cp linux/herdr/config.toml ~/.config/herdr/config.toml
hyprctl reload && hyprctl configerrors   # Lua modules are not auto-reloaded
```

Then `omarchy restart shell`.

## Shell (zsh)

Omarchy ships a **bash** rc chain only — there is no `default/zsh` — and this
machine has no `/etc/zprofile`, so `/etc/profile.d/omarchy.sh` never reaches zsh.
`linux/zsh/zshrc` therefore rebuilds the environment explicitly:

| What bash had | Where it comes from in zsh |
|---|---|
| `OMARCHY_PATH`, mise command-wrappers + shims, `~/.local/bin` | `source /usr/share/omarchy/default/bash/env-bootstrap` (POSIX, safe in zsh) |
| `brew shellenv bash` | `brew shellenv zsh` |
| `mise activate bash` | `mise activate zsh` |
| `starship init bash` | `starship init zsh` (prompt comes from `linux/starship.toml`) |
| `zoxide init bash` | `zoxide init zsh` |
| fzf key bindings | `/usr/share/fzf/key-bindings.zsh` |
| eza/fzf aliases | spelled out inline in the zshrc |

`zsh-autosuggestions` and `zsh-syntax-highlighting` load behind `-r` guards, so
a machine missing either package still starts a working shell.

**The prompt is per OS now.** `shared/starship.toml` is the Windows prompt (custom
catppuccin-powerline); `linux/starship.toml` is the `pastel-powerline` preset.
Changing one does not change the other.

## Correspondence with the Windows stack

Super-key-driven tiling → komorebi (Windows) / Hyprland (Linux). Bar with pill
widgets → YASB (Windows) / `omarchy-shell` (Linux). Video wallpaper → Lively
(Windows) / OWE (Linux), same media file. `shared/starship.toml`,
`shared/nvim/` and `shared/wallpapers/` are cross-OS. The mental model is the same;
only the tooling differs.
